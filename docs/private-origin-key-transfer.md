# Private origin-key transfer
The source directory must be separately prepared outside the caller checkout.

The deploy-traefik composite action accepts the optional `origin_keys_path` input. An empty value means that no dedicated key transfer is requested; the action still refuses any loose `certs/*.key` entry in the caller checkout. A non-empty value must name a separately prepared directory containing only direct-child origin key files with lowercase DNS-style dotted or hyphenated names of at most128characters ending in `.key`.

The helper is a source candidate for the trusted action. It is not an installed operations service, a caller-side secret generator, or evidence that any deployed consumer uses this path. The current webapp-management consumer remains pinned to `@v2.12.1`; no caller or infrastructure role is changed here.

## Custody and transport contract

The controller requires Linux POSIX filesystem support. The selected source directory must be owned by the executing UID, have mode `0700`, contain at most 32 direct regular files, and have no symlink, hardlink, nested path, or special file. Each key must be owned by that UID, have mode `0600`, one link, and contain 1–65,536 bytes. The batch is limited to 2 MiB. Access ACLs must have no effective group, other, or named-user/group permissions; default ACLs are refused. ACL inspection errors, unsupported ACL facilities, ownership changes, and inode changes fail closed. The preflight reads bounded file bytes only after these checks and discards them without output; transfer repeats the checks before opening the SSH process.

The action runs local preflight before tailnet connection. The general project rsync has an explicit `certs/*.key` exclusion, which also protects receiver keys from the operation's delete behavior. Loose legacy key files in the checkout cause a fixed refusal before rsync. If `origin_keys_path` is set, the adapter validates the complete bounded batch before opening SSH, then asks a fixed Python receiver embedded in the trusted action source to validate the destination directory, ACLs, and intended existing files. Key bytes are sent only after an exact ready acknowledgement bound to a fresh attempt nonce. The receiver creates owner-only same-directory temporary files, verifies their mode and ACL before writing, verifies per-file SHA256digests, stages the entire batch and requires exact input EOF before replacing any target. It fsyncs, atomically replaces only the named destination files, and checks the installed files again. It never removes keys omitted from the new batch. The helper resolves from the trusted composite action directory, outside project code.

Host, user, and path fields are complete-value validated. The receiver accepts only a fixed operation and bounded metadata; it does not execute caller commands or code. The helper allows one finite operation deadline of at most120seconds beginning before local validation; the receiver bounds its own reads and staging. These are userspace checks, not guarantees against stalled filesystem or process-creation syscalls. It caps metadata and receipts, rejects extra or malformed frames, and does not retry. A lost, late or mismatched acknowledgement after bytes may have been sent is reported as ambiguous. Failure and catchable cancellation cleanup verify inode and ownership before unlinking only temporary names created by that receiver attempt; it does not claim rollback of keys already atomically replaced.

The destination must already exist, be owned by the authenticated SSH UID, have mode `0700`, and have no default ACL or effective broad access ACL. Installed key files are owned by that UID with mode `0600`; this permits host root to read them. No group, named-user, or other reader is granted. Unsupported ACL checks, unsafe parent paths, pre-existing unsafe target files, or destination races fail before key bytes are sent where the receiver can determine that from its handshake.

## Adoption and acceptance limits

The actual Traefik host UID, container user namespace, service reader, destination ACL persistence, and caller source-directory lifecycle have not been established by these source changes. In particular, no claim is made that the deployed Traefik process can read keys installed for the SSH UID. The current Ansible recursive group/default ACL role may re-widen existing certificate paths; reconciling that role and proving its persisted effective ACLs are separate required work. A future caller must create and clean its private input directory safely, select an exact reviewed action revision, and retain an authorized recovery path before activation.

Tests use only synthetic invalid-key bytes in owned temporary directories, exercise Linux ACL xattrs and the actual embedded receiver locally, and replace the SSH process boundary with a local subprocess. They do not test semantic key validity, real credentials, real certificates, a live SSH target, a Docker container, or deployed privacy. This source candidate does not retire the existing `@v2.12.1` consumer or close S456 or WM-INF-91.

SIGKILL, power loss or an unreachable receiver can leave private temporary files. The sender cannot prove remote cleanup from a lost connection and does not automatically retry or remove unrelated files.

The controller launches the trusted helper with Python isolated mode (-I), excluding caller PYTHONPATH and working-directory imports. Both header and completion-receipt limits are8KiB, sufficient for the complete allowed32-key/128-character-name batch. Installed inode, owner, mode, link count, size and mtime are rechecked; rename legitimately changes ctime. The receiver cannot protect against a malicious host root or the credential-owning UID concurrently changing ACLs or key content. Effective Ansible/host isolation remains a deployment prerequisite.
